inputs: catálogo con contratos firmados, módulo bajo prueba
outputs: archivo de tests y tabla test a modo de falla
---

[INSTRUCCION]

No cambies el código de producción.

No inventes contratos nuevos.

Genera tests unitarios para los modos de falla cuyo estado del contrato sea **confirmado** en el catálogo de fallas.

Si encuentras contratos en estado **pendiente de decisión**, no escribas test para ellos; en cambio lístalos al final del proceso para completar dicho contrato.

[CAPA 1 - Sistema bajo prueba]

Módulo: `{{MODULO}}`

Framework de test: {{FRAMEWORK}}

Archivo destino: `{{ARCHIVO_DESTINO}}`

Funciones bajo prueba: {{FUNCIONES}}

[CAPA 2 - Modos de falla a cubrir]

- Utiliza el catálogo de fallos `{{CATALOGO}}` y usa la decisión de los contratos para escribir los unit tests bajo estos parámetros.
- No escribas tests para contratos que sigan en estado de "pendiente de decisión".

[CAPA 3 - Forma de salida]

- Entrega solo el contenido completo del archivo `{{ARCHIVO_DESTINO}}`.
- Usa {{FRAMEWORK}} para la creación de los tests.
- Cada test debe tener un comentario corto con el ID del modo de falla que cubre.
- Nombra cada test según el contrato que protege.
- Para la implementación de cada test usa la estructura AAA (Arrange, Act, Assert), con comentarios dentro de cada test.
- No pruebes detalles irrelevantes que no estén conectados con un modo de falla confirmado.

[SALIDAS ADICIONALES]

- Genera en una tabla los tests generados y el modo de falla que cubren.
- En caso de que existan contratos pendientes que no se pudieron convertir en test, lístalos y explica qué falta para implementar estos tests.
