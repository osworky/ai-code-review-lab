purpose: Corregir la lógica cuando los tests fallan por contratos confirmados.
inputs: tests rojos, catálogo con contratos firmados
outputs: cambio mínimo de código y explicación
---

Para corregir la lógica. Los tests ya existen y fallan por contratos confirmados en el catálogo de fallos.

- No cambies tests.
- No cambies el catálogo de fallos.
- No agregues dependencias.
- Analiza la salida real de cada test fallido.

Para cada test fallido:
- Con el ID identifica el contrato en el catálogo de fallos.
- Confirma si el test está relacionado con un contrato confirmado.
- Si el test es correcto, ajusta solo el archivo `{{ARCHIVO}}` para que se cumpla la lógica del contrato relacionado.
- Si el test no está alineado con un contrato confirmado, no cambies código: solo indícamelo.
- Haz los cambios mínimos y necesarios para que el test pase según el contrato, y explica qué ajustaste en la lógica de la función.

Nota de uso: los tests antiguos que fijaban el comportamiento previo y contradicen un contrato firmado **no se cambian dentro de este paso**; se listan y se actualizan aparte, en un commit propio, para que sea fácil revisarlos.
